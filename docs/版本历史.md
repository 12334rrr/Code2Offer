## 0.5.2-internal.2(2026-09-16)— 模式切换不再复用经济预览题库

### 根因与变更

阶段 2 的门控哈希此前只包含知识卡、模型和代码输入，遗漏了 `economy/balanced/deep` 模式。结果是先跑经济模式的 34 题后切到深度模式时，会错误命中缓存，无法获得发布所需的 100 题。哈希现纳入模式值，模式变化必然重新生成并校验题库；同模式重跑仍能正常复用。

### 真实验证

- `npm test`：**87/87** 通过。
- `example-demo` 深度模式 `run-0006`：阶段 2 按 100/100 题位和 13 批生成，补齐 6 个缺口后得到 100 题；阶段 3 完成 12 批对抗校验（pass 30 / fix 70 / flag 0 / unverified 0）。
- 质量报告：**A+ / 100**；有效引用率、引用边界通过率、已校验率均为 100%，引用文件覆盖率 91.7%，11 个题类均有覆盖，LangGraph lifecycle=`completed`。模型调用 28 次，0 网络重试、0 截断。

### 发布状态

- 此结果证明发布级深度管线可完成，但不能替代人工题目准确性评测或真实 VS Code UI 目检；故仍为内部构建，不发布 Marketplace，不升 1.0.0。

## 0.5.2(2026-09-16)— 输出分离:独立日志通道 + 独立产物目录

### 动机

- 直接诉求(用户):"整体插件的输出一直堆叠在一个输出的控制台中,前一次和后一次不好分辨——增加一个自动开启新的输出端口,不要前一次和后一次在一起。"
- 同类问题在**产物层**同样存在:前后两次生成默认都写 `<仓库>/interview-output/`,后一次覆盖/混入前一次,报告、questions.json、缓存全部搅在一起。

### 变更

**日志层(src/core/logger.ts + runner)**:新增 `withLogSink()`——基于 `AsyncLocalStorage` 给一次管线运行的**整棵异步调用树**挂上下文专属日志出口(跨 await/timer 传播,多任务并行互不串线);上下文内的行**同时**送全局 sink 与专属 sink。`RunOptions.logSink` 供宿主注入;CLI 不传,行为不变。

**扩展(vscode/src/extension.ts)**:
- 每次生成自动创建输出通道 **「代码转面试 · 仓库名 · 启动时刻」并自动弹出**(`taskChannel.show(true)`)——输出面板直接切到本次专属通道;
- 主通道「代码转面试」保留全部运行的完整历史(深度排查兜底);任务 🗑 移除/清空记录时连同其专属通道一起 dispose;
- 任务 tooltip 显示 `日志通道` 名;失败时「查看日志」直接跳本次专属通道。

**产物层(src/core/runs.ts 新模块)**:
- 默认(未显式指定输出目录)每次生成自动新建 **`<仓库>/interview-output/runs/run-NNNN`** 独立目录(零填充序号,杂项目录/同名文件忽略,删早期 run 不回退编号),前后两次产物互不覆盖;
- **增量接续不丢**:`carryForwardIncrement` 把上一次 run 的门控状态(state.json)、画像/模块卡/题库/JD 门控输入、校验断点(.verify-progress.json)、LLM 缓存(.cache/)携带进新 run——仓库没变的部分照常命中缓存,几乎零成本;**最终产物与 .run-lock 绝不携带**;
- 运行锁上移到输出根(与旧版同粒度:同一仓库同时只有一条管线);
- 显式 `--out` / 扩展里选「固定目录/自定义目录」= 旧覆盖语义,不建 runs/;
- `repoRootOfOutput` 从 run-manifest 反推仓库根(rehearse/topup/evaluate 的凭据绑定不受目录变深影响);扩展「打开报告/产物/质量报告」定位顺序:上次目录 → 最近完成的 run → 旧布局根。

**工程**:新增 `src/tests/runs.test.ts`(10 用例:编号分配/杂项忽略/携带清单负面断言/latest/repoRoot/logger 上下文隔离与并行隔离);删除两个 0.4 期过期回归脚本(current-0.4-regressions.cjs 断言树 4 条目、extension-regressions.cjs 沙箱只 mock 旧 import 列表——0.5.0 起双双失效,覆盖面已由 src/tests + activation-smoke 接管);`.gitignore` 加 `JD/`(个人岗位描述,不入库)。

### 验证(全部实跑)

- `npm test` → **78/78 通过**(68 + 新增 10);vscode typecheck 零错误;vsix 重打包 `code-interview-prep-0.5.2.vsix`(7 files,79.95 KB);
- `node audit/activation-smoke.cjs` → 9 组断言全绿(生成流程 stub 已适配新增的「输出方式」quickpick:取第一项=自动独立目录);

### 产物与发布状态

## 0.5.0(2026-09-16)— A+ 工程升级(本地构建)

### 动机

真实大型仓库日志显示 61 次模型调用、约 109 万输入 token、约 90 万输出 token、阶段 2/3 各约 25 分钟；同时暴露了全局 token 扩容、浏览器 profile 污染、阶段 1 大模块解析失败和引用校验断点复用风险。

### 变更

- `src/core/policy.ts` 统一 requestType、模型、温度、JSON、预算硬上限、超时、重试、并发组、缓存和 reasoning 策略；`DeepSeekClient` 将扩容限制在单次逻辑请求，永久 HTTP 错误不重试，429/408/5xx 尊重 Retry-After，取消立即中止，记录按类型调用与 token。
- `profiler.ts` 增加便宜目录快照、浏览器 profile/构建缓存过滤、100–300KB 分段秘密扫描与跳过原因统计；`chunker.ts` 对超长行完整拆块，不静默截断，并在分块阶段二次拦截秘密。
- 阶段 1 大模块拆局部证据卡并按局部缓存；阶段 2 采用 10/8 题批次和 3 批并发；阶段 3 动态装箱、3 路并发、串行 checkpoint 写入和题目输入指纹。
- `quality.ts` 生成质量门禁、Claim Ledger 和 evidence graph；最终等级由确定性指标计算，不能由模型自评。`run-manifest.json` 与 `dependency-manifest.json` 记录快照、阶段哈希、调用统计和降级摘要，不记录密钥。
- HTML 报告新增质量等级、深浅主题、组合筛选、搜索高亮、弱项练习、学习进度导出和题库版本隔离；Webview 异常结构只安全降级系统浏览器。扩展生成前选择模式/文件数/输出目录并修正重复警告与取消文案。

### 验证与限制

- 本地单测覆盖 API 合约、快照/秘密扫描、过滤、引用规范化、并发 checkpoint、质量门禁和 HTML 安全；实际数字以本次验收报告为准。
- 0.5.0 只本地构建，不推送 Git、不发布 Marketplace；真实付费 API、真实大型仓库优化 A/B、真实 VS Code UI 观感需单独记录，未验证项目不得写成通过。
