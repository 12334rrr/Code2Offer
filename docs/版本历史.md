## 0.4.0(2026-09-15)— 进度时间轴 + 并行任务管理

### 动机

- 直接诉求(用户):"不小心多次点击可以叉掉对应的进程;查看进程的过程使用时间轴带节点的情况;优化展示 UI,使读者清晰看到进行的操作与进度。"
- 背景痛点:0.3.0 只有一个转圈通知条,看不到"现在在哪一步、每步花了多久、哪些是缓存秒过";扩展用全局标志禁止第二个任务,多仓库工作流被卡死。
- 同轮定名:项目正式命名 **Code2Offer**,建仓推送 GitHub(`12334rrr/Code2Offer`,首提交 `1ae389d`);商店 ID 保持 `DawnofHope.code-interview-prep` 以不破坏老用户升级,品牌走 `displayName`。

### 变更

**runner(src/core/runner.ts)**:新增 `RunOptions.onStage` 结构化阶段事件——8 节点 `profile/read/questions/verify/rewrite/jd/assemble/done`,状态 `start/done/cached/skip`,带逐段用时与备注(如 `pass 84 · fix 9 · flag 4 · 未覆盖 3`、`118 文件 / 14 个精读文件`)。CLI 不接这个回调,行为零变化。

**扩展(vscode/src/extension.ts 重写)**:
- 侧栏树渲染任务 → 阶段节点时间轴:✓ 完成(逐段用时)/ 💿 门控命中缓存复用 / ⟳ 进行中实时秒表(1s ticker)/ ⊘ 跳过 / ✗ 失败 / ■ 已取消 / ○ 等待中;悬停 MarkdownString tooltip 给完整时间轴。
- **多任务并行**:`Map<outDir, LiveTask>`,不同仓库各自跑、各自取消;**同仓库误点去重**:弹「查看进度 / 取消并重新开始」(后者 await 旧任务 settle 后沿用原 JD 参数重开,已花的钱不白花)。
- 内联按钮:运行中任务 ✕(取消,缓存保留)、已结束任务 🗑(移除记录);面板标题栏「生成 / 全部取消」;`setContext('codeInterviewPrep.hasRunning')` 控制按钮显隐。
- 树条目 `TaskTreeItem/StageTreeItem` 子类携带任务引用,命令参数直取,不再猜"当前任务"。

**工程与文档**:根 `package.json` bin 更名 `code2offer`;`--version` → 0.4.0;冒烟脚本加 [1b] 组(cancelTask/dismissTask 空参安全、cancelAll 无任务提示)。CLAUDE.md / 根 README / vscode/README(商店页,含时间轴 ASCII 示意与图标含义表)/ vscode/CHANGELOG 同步。

**提示词存档全量化**(响应"所有提示词原样保存"要求):导出器从 13 份补到 **17 份**——新增 `02c 对比块补齐`、`02d 要点实质化`、`03b 标红题重写`、`07 自评四评委`;`STAGE2_TOPUP_USER_HINT` 登记进 02 存档。配套小重构(逐字节等价,缓存键不变):evaluate.ts 四条内联评委 system 提升为 prompts.ts 导出常量;stage2Questions.ts 3.5 的 user 拼接改为共享 `stage2FlagRewriteUser()`——**存档与运行代码同源**。CLAUDE.md 新增「用户长期要求」三节(提示词存档 / 改完即推送 / 版本历史成文)。

### 验证(全部实跑)

- `npm test` → **46/46 通过**(本版本未新增测试用例:runner 事件与扩展 UI 属展示层;evaluate/stage2 重构以"输出逐字节不变"原则保证,由全量测试回归兜底)。

## 0.3.0(2026-09-15)— 全面安全与正确性修复

### 动机

运营症状:**商店版"运行了很久也没有完成",本地正常**。触发了按最严标准的整项目审计(`audit/代码全面审计报告.md`,逐文件行号级证据),产出 4 项 P0 安全 + 8 项 P1 正确性 + 一批 Q/T 项,全部修复,过程见 `audit/修复实施记录-0.3.0.md`。

### 变更(按审计编号)

- **S-1 凭据可被仓库 .env 劫持端点**(任意人 `git clone` 恶意仓库放进工作区即可把用户密钥引到攻击者地址):端点与凭据**同源绑定**(仓库 .env 的 BASE_URL 仅当它自带密钥才生效)+ BASE_URL 强制 HTTPS(localhost 例外)→ `src/tests/config.test.ts`。
- **S-2 扩展把密钥写进 process.env 造成跨仓库污染**:loadConfig 改 ranked sources(env=1 / 可信 .env=2 / 仓库 .env=3),一次一解析显式传参,扩展不再写环境变量。
- **S-3 .env/私钥可能进模型输入**:profiler 敏感文件拒绝清单 + 内容级密钥特征扫描,独立于 .gitignore 永远生效 → `src/tests/profiler.test.ts`。
- **S-4 错误消息回显完整密钥**:`maskKey()` 只留前 8 位,覆盖全部错误路径。
- **R-1/R-2 门控哈希不覆盖内容**(等长改码整链命中旧缓存):画像/精读/校验哈希全部改为内容基 → `src/tests/runner.test.ts`。
- **R-3/R-4 校验环缺陷**(模型失败当"通过";断点跨题库复用旧裁决):新增 `unverified` 第四态;断点带输入指纹。
- **R-5 配额漂移**:补题按类别×难度缺口定向,`topup` 上限保护。
- **R-6/R-7/R-8**:JD 输出形状校验防毒缓存;3.5 重写保留原始裁决、校验报告重算;CLI 参数解析重写(布尔旗标吞路径、`--force` 静默失效)→ `src/tests/cli-args.test.ts`;评委结果按内容缓存(可复现)。
- **报告**:内联事件改事件委托(Webview CSP 下可用)、掌握度 localStorage 按仓库命名空间、搜索 150ms 防抖、Markdown 单元格清洗 → `src/tests/html-report.test.ts`。
- **提示词 v2**(`audit/提示词工程审计与改进报告.md` 8 项缺陷):`PROMPT_VERSION='2'` 整体失效旧缓存;讲解禁行号轰炸/1 分钟 150 字硬上限/锚点制;亮点钩子前置;缺点结构性方案+技术栈一致;评审 60 字上限先分后题。
- 工程:`npm test` 脚本修 Node 24 目录展开 bug(`node --test "dist/tests/*.test.js"`);prepublish 加类型检查;`.vscodeignore` 排除源码;sourcemap 排除出包。
